Laboratorio: segmentación con VLAN entre un switch core y FortiGate

Laboratorios20 oct 20268 min de lecturaPor Equipo técnico de CY Solutions

Uno de los cambios con mayor impacto en la seguridad de una red empresarial es también uno de los más simples: dejar de tener a todos los equipos en la misma red. En este laboratorio separamos usuarios, servidores y WiFi de invitados en VLAN independientes y dejamos que un FortiGate decida qué tráfico puede pasar entre ellas.

Objetivo

  • Crear tres VLAN en el switch core y llevarlas al FortiGate por un único enlace troncal.
  • Hacer el enrutamiento entre VLAN en el FortiGate, para que todo el tráfico entre segmentos pase por políticas de firewall.
  • Permitir que los usuarios lleguen a los servidores solo por los servicios necesarios, y aislar por completo a los invitados.

Topología

VLANNombreRedPuerta de enlace
10USUARIOS10.10.10.0/2410.10.10.1
20SERVIDORES10.10.20.0/2410.10.20.1
30INVITADOS10.10.30.0/2410.10.30.1

Puede reproducir este laboratorio en EVE-NG o GNS3 con una imagen FortiGate VM y un switch IOSvL2. Ajuste los nombres de las interfaces a su entorno.

1. Configuración del switch core

Creamos las VLAN, configuramos el puerto hacia el FortiGate como troncal y asignamos los puertos de acceso.

Switch core (Cisco IOS)

vlan 10
 name USUARIOS
vlan 20
 name SERVIDORES
vlan 30
 name INVITADOS
!
interface GigabitEthernet1/0/48
 description TRONCAL-A-FORTIGATE-port2
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
!
interface range GigabitEthernet1/0/1 - 20
 description USUARIOS
 switchport mode access
 switchport access vlan 10
 spanning-tree portfast
!
interface range GigabitEthernet1/0/21 - 24
 description SERVIDORES
 switchport mode access
 switchport access vlan 20
 spanning-tree portfast

En plataformas antiguas puede ser necesario agregar switchport trunk encapsulation dot1q antes de switchport mode trunk. Los puntos de acceso que publican el SSID de invitados se conectan a puertos en la VLAN 30, o a un troncal si el AP maneja varios SSID.

2. Interfaces VLAN en el FortiGate

Cada VLAN se crea como una subinterfaz de port2, con la dirección IP que servirá como puerta de enlace.

FortiGate (FortiOS CLI)

config system interface
    edit "VLAN10-USUARIOS"
        set vdom "root"
        set interface "port2"
        set vlanid 10
        set ip 10.10.10.1 255.255.255.0
        set allowaccess ping
        set role lan
    next
    edit "VLAN20-SERVIDORES"
        set vdom "root"
        set interface "port2"
        set vlanid 20
        set ip 10.10.20.1 255.255.255.0
        set allowaccess ping
        set role lan
    next
    edit "VLAN30-INVITADOS"
        set vdom "root"
        set interface "port2"
        set vlanid 30
        set ip 10.10.30.1 255.255.255.0
        set role lan
    next
end

3. Políticas de firewall

El FortiGate niega por defecto todo tráfico que no esté permitido por una política. Por eso solo creamos lo que sí debe pasar:

config firewall policy
    edit 0
        set name "USUARIOS-A-SERVIDORES"
        set srcintf "VLAN10-USUARIOS"
        set dstintf "VLAN20-SERVIDORES"
        set srcaddr "all"
        set dstaddr "all"
        set action accept
        set schedule "always"
        set service "HTTPS" "DNS" "SAMBA"
        set logtraffic all
    next
    edit 0
        set name "USUARIOS-A-INTERNET"
        set srcintf "VLAN10-USUARIOS"
        set dstintf "wan1"
        set srcaddr "all"
        set dstaddr "all"
        set action accept
        set schedule "always"
        set service "ALL"
        set nat enable
    next
    edit 0
        set name "INVITADOS-A-INTERNET"
        set srcintf "VLAN30-INVITADOS"
        set dstintf "wan1"
        set srcaddr "all"
        set dstaddr "all"
        set action accept
        set schedule "always"
        set service "HTTP" "HTTPS" "DNS"
        set nat enable
    next
end

No existe ninguna política desde VLAN30-INVITADOS hacia usuarios o servidores, así que ese tráfico queda bloqueado por la política implícita.

4. Verificación

En el switch, confirme que el troncal está activo y transporta las tres VLAN:

show interfaces trunk
show vlan brief

Desde un equipo de invitados (por ejemplo 10.10.30.50), un ping a un servidor en 10.10.20.10 debe fallar. En el FortiGate puede confirmar el motivo con el depurador de flujo:

diagnose debug flow filter addr 10.10.30.50
diagnose debug flow show function-name enable
diagnose debug flow trace start 10
diagnose debug enable

La salida debe mostrar Denied by forward policy check (policy 0): el tráfico fue descartado por la política implícita. Al terminar, desactive la depuración con diagnose debug disable.

Conclusiones

Con pocos cambios, la red pasa de ser un único dominio donde cualquier equipo puede alcanzar a cualquier otro, a tener segmentos controlados y registrados. A partir de aquí es natural agregar perfiles de seguridad (antivirus, IPS, filtrado web) a cada política, y llevar los registros a un sistema de monitoreo.
